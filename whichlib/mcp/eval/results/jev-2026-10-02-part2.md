## Reading it

- On the held-out niche needs (written before any Jev run, accept names checked against the GitHub API), Jev lifts hit@1 from 60% to 90% and MRR from 0.72 to 0.93. Today's ranking is *worse* than GitHub's own relevance order there (70% / 0.78); Jev rankings beat both.
- The three layouts tie on hits. Per-candidate (combined) used ~0.8x the input tokens of shared per judgment (estimate: its 3 questions shared one request) and fits 20 candidates per request instead of 12. Splitting the judgment does not help.
- Remaining niche misses: "text diff" (jsdiff never retrieved by GitHub search: retrieval, not ranking) and "configuration loader" (gookit/config first, koanf second: a fair pick).
- Choice for integration: combined (per-candidate) layout, ~3 requests per call, `score x GitHub position x Jev` (Jev replaces the word-match factors), pinned `jev-1.13.0`, whole pool before the shortlist. ~10-12k input tokens per recommend call at $0.042/Mtok = ~$0.0005, ~350 ms added.
